# Where Tohru can use native Pleamar

Audited Tohru main at `fd8c4b5f4485fe15d4bb7c74e1397f37fe855e08`. The strongest immediate changes are in scene wiring. One downstream rendering patch has a concrete upstream replacement when the project next updates Pleamar.

## Implementation status

The first four recommendations are implemented on the independent audit branch against Pleamar 0.7.27. The findings and proposed checks below describe the original audit at `d5b3b60`.

**Verification scope.** The isolated native checks used prebuilt Nix-store Pleamar 0.7.27 binaries, the sandbox Sway display, a private session bus, separate settings/cache/socket paths and a shared GPU reservation. The MPRIS scene used the production bar/media controllers without the other bar services. The Settings device helper was a fixture. No microphone hardware or external account was needed.

Lua 5.4.9 passed the Settings process and corner-size tests, the bar and Calendar controllers, media controller, Information controllers/overview/power, and sound reconciliation and OSD integration. Both embedded Luau scenarios in `tests/settings-ui/logic.rs` also passed when executed under Lua 5.4.9 with a clamp shim. The role-launch test and both loopback remote-art tests passed. `tests/settings-ui/contrast.py` failed identically on the report-only base and the implementation because it expects literal colors where the scene references palette tokens. The heavy Rust suite, Nix build, whole-bar compositor acceptance and portability integration remain unverified. CPU/RAM admission was unavailable.

**Portability merge touchpoint.** At unmerged `6cef2f4`, `shell/settings/controller.luau` adds shortcut operations, a status query on open, and periodic refresh on the shortcuts page. Preserve that query in the single reopen handler after successful reload. Retain its navigation, async results and managed font settings when reconciling edit/publication callbacks. The independent main-base commits include none of the portability implementation.

**Deferred choices.** Continue shipping patch 0028 with the current pin. Its removal requires the future-rebase acceptance checks in finding 5 below. Remote HTTP(S) album art remains supported and its cache and fetch limits still apply.

## Findings on the audited base

**1. Settings owns two reopen handlers.** In `shell/settings/controller.luau` the handler refreshes from the process snapshot, starts `devices()` with the selected source, and shows the window. In `shell/settings/settings.luau` a later handler reloads the files, publishes corner size and refreshes again. On row edits, `activate` refreshes and calls `applied`, which refreshes again. Native Luau `on` appends handlers in registration order. A fixture with native-style multicast, a recorded device request and a changed source on reload produced **two row publications, probe for “before”, effective source “after”** on one reopen. That can show a status for the wrong microphone. [Pinned handler registration and dispatch](https://github.com/k4ditano/pleamar/blob/dc902feb0ee9058b7db7c2bc2c9d59d9f655fd86/src/logic_luau.rs)

Use one open handler with an explicit sequence. Show the window, reload once, publish the editor and rows from that snapshot, then enumerate devices. On reload failure show the error and retain usable previous values. Let one function publish after a successful edit. Preserve search, keyboard selection, navigation history, managed override forwarding, error messages and the generation check on async device results. This is a small change with moderate interaction risk. It removes duplicated ordering decisions. First update `tests/settings-ui/process.lua` to supply the current default for `assistant.reduced_motion` and to append callbacks as the runtime does. The existing fixture failed in `switch` before opening. Close, change the configured source, reopen, then return two probe completions out of order. Check the published source, corner field, visible state, number of row publications before async completion, and behavior when the bar is unavailable. Apply after reconciling the unmerged Settings page additions.

**2. MPRIS already supports independent listeners in one VM.** `shell/bar.luau` constructs `media` and passes `media.observe` to `shell/bar/controller.luau`. Its media watcher formats the headline and manually forwards the full native report to `shell/media/controller.luau:observe`. Pinned `sys.watch` appends each function to the service-name vector, starts the service only for the first, and dispatches the same converted report to every listener. Across VM reloads the platform hub rebinds the listener and replays its last report. This applies to two Luau watchers in one VM. A declarative service alias has a different subscription tag, and separate processes have separate hubs. Patch 0015 adjusts startup patience, and 0024 supplies player rows and volume. Neither creates the multicast behavior. [Dispatcher](https://github.com/k4ditano/pleamar/blob/dc902feb0ee9058b7db7c2bc2c9d59d9f655fd86/src/logic_luau.rs) · [Service hub](https://github.com/k4ditano/pleamar/blob/dc902feb0ee9058b7db7c2bc2c9d59d9f655fd86/src/platform/mod.rs)

Register the popup observer when constructing that controller. Keep both initial registrations synchronous and preserve standalone bar behavior. A later registration in an already running VM has no individual immediate replay guarantee. Treat the report as read-only. Retain chosen-player resolution, pending seek/volume gestures, artwork callback validation and the headline while the popup is open. OSD is different: it observes the sound controller's *processed* facts, so ordering matters there. Low effort and risk, with one less cross-controller dependency. Extend the media/bar fixtures with two listeners, one backend start, first report, removal of a player mid-drag, and reload while paused. Confirm with an isolated MPRIS player before release.

**3. Calendar can ignore same-date ticks.** Pinned `platform/clock.rs` emits local year, month and day on startup and each minute. `shell/calendar/controller.luau` rebuilds `model.cal_days` in `publish` on each report, even with the calendar closed. Calling the production callback twice for 22 November 2026 replaced the 35-row grid twice across those two reports. Use its existing `same(a,b)` comparison to return early on subsequent reports with identical date fields. Keep the first publication after VM replacement and every user-driven refresh. A date change in either direction still needs publication even when viewing another month. The bar retains minute updates and its 12-hour display. Native formatted time uses 24 hours and native formatted date zero-pads the day. Low effort and risk. The benefit is fewer model writes with no new service or timer. Add a same-date identity/write-count case to `tests/calendar/controller.lua` alongside midnight, leap day, closed/reopened popup and retained month. [Pinned clock](https://github.com/k4ditano/pleamar/blob/dc902feb0ee9058b7db7c2bc2c9d59d9f655fd86/src/platform/clock.rs)

**4. Information has a broken standalone import.** `shell/info/entry.luau` requests `require("../bar/rail")`. The pinned loader explicitly rejects a path segment equal to `..` before reading the file. The patches leave that check in place. The integrated `shell/bar.luau` already injects the rail correctly. Use a scene-local `rail.luau` link and `require("rail")` as in `shell/launcher/entry.luau`. The launcher's rail is already a Git symlink to `../bar/rail.luau`. This restores the documented standalone information popup and shared rail, with no additional copy or loader permission. Low effort and risk. Check package and development layouts preserve/resolve the link. Execute the standalone logic with role bindings, open Information and switch pages. A scene syntax check alone does not execute the import. [Pinned module loader](https://github.com/k4ditano/pleamar/blob/dc902feb0ee9058b7db7c2bc2c9d59d9f655fd86/src/logic_luau.rs)

**5. Patch 0028 has an upstream successor.** The pin's `src/gpu.rs:DrawList::element` picks the main frame or the first intersecting view. A large lock backdrop can be clipped on the taller monitor. `0028-lock-views-together.patch` takes the union of all intersecting views (including the main frame), with the main frame as fallback. Upstream `element_frame` computes that same union and fallback. Its regression covers a turned monitor beside a landscape monitor, a single-view element and the main surface alone. This is a rendering equivalence independent of the password authority. Delete this one patch **only on a tested upgrade to 0.7.30 or later containing the fix**. Low effort for the patch itself, high integration risk for the runtime rebase. It removes a downstream GPU hunk and moves the geometric regression upstream. [Upstream implementation and test](https://github.com/k4ditano/pleamar/commit/9e9344f989fd73607186eae5d4ee6696ae73b2fd)

The same release changes lock startup, initial state, output copies and monitor arrival. 0.7.31 also routes key/focus rules to the copy owning the keyboard and fixes surface indices when inserting copies. These are partial overlaps with Tohru's focus work and change code touched by its authority. They do not establish equivalence for 0010/0011/0016/0018 or the unlock permit. Rebase the whole series on a scratch branch, run upstream geometry tests and Tohru lock fixtures, then use a private compositor with mixed orientations, hotplug, input on both heads, rejected authentication, an attempted scene-only release, logic reload and a valid unlock. Check the compositor-confirmed ready event where the portability branch depends on it. No upgrade on the strength of this one patch. [Upstream lock change](https://github.com/k4ditano/pleamar/commit/c9b68999d0c8634ab2d8a519c74cccd46b7c7728) · [Per-copy keyboard change](https://github.com/k4ditano/pleamar/commit/a967bd8ab92eaed0960bbf2b7f6f60579b287cdb)

**6. Remote art is a product decision.** Pinned `platform/mpris.rs:art_path_in` decodes file URLs and materializes supported base64 data images. It returns HTTP(S) URLs unchanged. `shell/media/controller.luau:resolve_art` and `bin/tohru-media-art` add fetching, retries, format detection, timeout/redirect/byte limits and a bounded on-disk cache. 0024 gives access to each player's art as well as the selected player's. No complete native substitute was found. If remote covers have low value to users, accept the current empty-art fallback for HTTP(S), keep native local/data artwork, and remove only the fetch-related code, permission and packaging after that choice. The cost is visible in the popup and player list for remote-only sources. Existing cache ownership/cleanup would need an explicit decision. Moderate maintenance reduction, small implementation effort, real visual regression. Exercise file, data, remote-only, rapid track changes and no-art sources using `tests/media/controller.lua` and `tests/media/remote-art.py`. No evidence about how frequently users see remote-only art. [Pinned MPRIS artwork handling](https://github.com/k4ditano/pleamar/blob/dc902feb0ee9058b7db7c2bc2c9d59d9f655fd86/src/platform/mpris.rs)

## Coverage and retain decisions

| Area and local evidence | What native Pleamar supplies and what Tohru owns |
|---|---|
| Settings, status and IPC — `runtime/src/settings.rs`, `runtime/pleamar/bindings/settings_luau.rs`, `shell/bar.luau:publish`, `shell/settings/settings.luau:applied`, `bin/tohru` | **Partial.** Launcher already uses stock per-owner `files.read/write` for its JSON usage history. That API lacks layered TOML, comment-preserving writes, managed provenance and in-memory overrides surviving VM reload. Native `sys.call("say", …)` sends one line and returns command errors, without returning the other VM's state. CLI multi-command sends and streaming `watch` are useful transport, but do not implement atomic cross-process settings transactions. Keep the owner, settings status schema and override replay. |
| Bar, bell and launcher lifetime — `shell/bar/{bell,launcher,workspace}.luau`, `shell/launcher/{output,controller}.luau` | **Partial.** The bell and launcher already exchange native events. The bell requests a fresh report after restart. The launcher check clears stale open state when its peer goes away. A fact-change listener in the bar cannot observe peer death. A persistent CLI watcher would need reconnection, initial replay, cancellation and display selection. Keep the existing narrow protocol. Native workspace reports power the ribbon. Unmerged portability work already separates live outputs from workspace availability. |
| Layout, controls and input — `shell/settings/window.plm`, `shell/launcher/{geometry,search,fuzzy,usage}.luau`, `shell/services.plm` | **Partial.** Stock `lib/ui.plm` has Switch, Radio, Segmented, Tile and Card. Settings already uses native model-backed columns, a search input and a viewport. A Switch has its own press zone. Dropping it inside the existing full-width row introduces a second target and does not preserve row activation, disabled state, Tab/arrow/Return behavior or readable labels by itself. The sample launcher performs a capped substring filter. It lacks Tohru's localized-name and keyword ranking, usage/pins and placement geometry. Keep those behaviors. Validate pointer, keyboard-only and semantic inspection on any future widget change. |
| Info, network, Bluetooth, tray, audio and notifications — `runtime/src/info/`, `shell/{info,network,bluetooth,tray,sound,osd}/controller.luau`, `shell/notifications/notifications.luau` | **Mixed.** Native services already deliver battery, clock, network devices, BlueZ, tray menu trees, Pulse/MPRIS and notification events. The information snapshot joins OS/hardware, mounts, users and generations; a battery or clock report cannot supply that. Bluetooth's declarative pairing fields enable the agent, while `reconcile(report)` derives active/connecting rows by address. Dropping either registration needs full device-model and pairing-ID tests. Sound coalesces drags against backend acknowledgements. OSD suppresses first observation and remains hidden while the sound popup is open. Notifications owns history/DND presentation and hover timeout holds. Keep those ownership and input distinctions. |
| Processes and session — `bin/tohru-{run,launcher-run,settings-run,session-run,polkit-run,notifications-run,lock,greeter}`, `shell/session/menu.luau:execute`, `nix/runtime-wrapper.nix` | **Partial.** Native `--scene`, `--answer-as` and service permissions already do most launching. The scripts also select role, scene directory, overrides and helper PATH. The Nix wrapper supplies dependencies for detached app launch. Merging all roles behind one generic environment risks changing which authorities are installed. The pin's `session.lock` and `session.suspend` return after spawning loginctl/systemctl. Chaining them cannot enforce the current exit-status check, much less prove a compositor locked. Portability already strengthens this pathway. Keep separate lifetimes, including single-instance bus owners. |
| Wallpaper and desktop effects — `bin/tohru-wallpaper:{scan,status,apply,seek}`, `shell/wallpaper/controller.luau`, `hyprland/{sheet,recede}.cpp`, `hyprland/LAUNCHER-CONTRACT.md` | **Partial.** Native files are scene-owned data. Window thumbnails and frozen screen captures describe compositor content. None implement a per-output media player with preview, seek, revert and persisted assignments for a user's wallpaper directory. Native layer placement doesn't implement the compositor plugin's launcher transition or focus restoration. Keep those paths conditional on available backends. Defer output discovery and standalone ownership to portability. |
| Animation and rendering — `shell/bar/{rail.luau,rail-springs.plm,rail-rules.plm,ribbon.wgsl}`, `shell/assistant/{puppet.luau,full-body.luau,dragon.plm}`, `shell/lock/styles/` | **Already native plus authored motion.** Scene springs, expressions, shaders and images render the movement. Controllers select rail goals and gesture reversals, sprite poses, travel and mouth state. A generic transition cannot reproduce registered full-body poses, interruption or reduced-motion choices. Retain content and behavior. Treat the separate 3D exploration as outside this production audit. |
| Assistant, voice and Discord — `shell/assistant/{controller,voice}.luau`, `bin/tohru-{assistant,voice,discord}`, `desktop/src/discord:{Client,Broker}` | **No equivalent for the application protocol.** Native run/spawn/read/write/cancel primitives provide process I/O. A process exit cannot retract partial speech, distinguish generation IDs, decide whether a speculative draft may commit, roll back a conversation or choose between local and Orca state. Patch 0040 allows stderr in the journal independent of the streamed stdout protocol. Keep credential handling and author/channel/guild validation at the REST boundary, including revalidation before requests and the required allowed-user ID. Use fixture traffic for regression checks. |
| Authentication — `runtime/pleamar/bindings/{lock,greeter}.rs`, `runtime/src/greeter/{state,ipc}.rs`, `shell/{lock,polkit,greeter}/controller.luau` | **Partial.** Upstream provides an ext-session-lock surface, PAM and polkit primitives. Tohru couples release permission to the current lock cycle, keeps secret input outside scene logic, and separates greetd pre-session authority from desktop roles. Confirmed readiness, cancellation and cleanup of credentials matter across reload, compositor refusal and output removal. Keep native guards and test separately from visual equivalence. |

### Original verification and proposed sequence

1. **First change the fixtures.** The existing production-module bar/calendar and media tests passed under Lua 5.4.9. The recording-process role-launch test passed. The unmodified Settings process fixture failed on its missing reduced-motion setting. An augmented local fixture reproduced the stale-source result. These checks exercise logic and wrapper arguments. They do not exercise Wayland, PAM, MPRIS transport or rendering.
2. **Land independent pin-compatible changes.** Start with Settings after the portability edits settle, or take the Calendar, media-dispatch and standalone Information changes independently. For the media and Information changes, test actual initial service delivery, reload and file/module resolution in private runtime instances. Preserve focus, public events, role boundaries and the existing visuals.
3. **Keep portability's acceptance matrix as the integration gate.** I read the unmerged `malinoskj2/wayland-portability` tree at `6cef2f4b0a9f6337cb47d6286197433b22a82a44`, including `docs/standalone.md` and `docs/portability-verification.md`. It already covers Wayland output discovery, fallback protocols, service ownership, font resolution, shortcuts, diagnostics and lock-confirmed suspend. Its combined build and live acceptance remain open. Avoid parallel implementations here.
4. **Track the GPU patch for the next planned rebase.** The scheduler mode file and `resource-run` were unavailable in this environment. I did not run heavy builds, render, exercise a live compositor, authenticate, access Discord or measure performance. The patch application check validates the shipped series on the pin, not a rebased build. Seek a separate product decision before dropping remote artwork.
